## Крок 1. Запустіть SQL-міграцію

1. У Supabase відкрийте потрібний проєкт → **SQL Editor** → **New query**.
2. Вставте повний вміст `supabase/admin_access.sql` та натисніть **Run**.
3. Перевірте, що запит завершився без помилки. Міграція створює захищені таблиці головних адміністраторів і винятків, змінює правило створення профілю при реєстрації та забороняє запис профілів напряму з браузера.

Не запускайте одночасно цей файл і повний `schema.sql`: правила міграції вже додані в кінець `schema.sql` для нової інсталяції.

Перед запуском перевірте, що ці дві адреси відповідають вашим головним адміністраторам. Якщо головні адміністратори мають бути інші, замініть їх у `INSERT INTO public.super_admin_emails` у `admin_access.sql` (і в однойменному блоці наприкінці `schema.sql`) до запуску міграції.

## Крок 2. Розгорніть серверну Edge Function

Функція потрібна для надання ролі адміністратора й видалення Auth-облікового запису. Секретний ключ Supabase використовується лише на сервері.

### Через Supabase CLI у Windows

Для цього способу не потрібні Node.js, npm чи Docker. Supabase CLI надсилає функцію до хостингу через API.

1. Відкрийте звичайний **PowerShell** (не обов'язково від імені адміністратора).
2. Якщо Scoop ще не встановлений, виконайте:

   ```powershell
   Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
   irm get.scoop.sh | iex
   ```

   Якщо PowerShell запитає підтвердження зміни політики, введіть `Y`. Це налаштування лише поточного Windows-користувача. Інструкція Scoop: [scoop.sh](https://scoop.sh/).

3. Додайте офіційний каталог Supabase та встановіть CLI:

   ```powershell
   scoop bucket add supabase https://github.com/supabase/scoop-bucket.git
   scoop install supabase
   supabase --version
   ```

   Остання команда має показати версію CLI. Якщо `scoop` або `supabase` не розпізнається, закрийте PowerShell, відкрийте його знову і повторіть команду.

4. Перейдіть у корінь папки сайту. Наприклад:

   ```powershell
   cd "C:\Users\Роман\Downloads\grafik-zmin-main"
   ```

   Переконайтеся, що у цій папці існує `supabase\config.toml` і `supabase\functions\admin-management\index.ts`. Цей проєкт уже має конфігурацію Supabase, тому **не запускайте `supabase init`**.

5. Увійдіть до свого Supabase-акаунта:

   ```powershell
   supabase login
   ```

   Відкриється сторінка входу або CLI попросить вставити access token. Увійдіть до акаунта, який має право розгортати функції в проєкті. Access token створюється в Supabase Dashboard → **Account → Access Tokens**. Не надсилайте його нікому й не додавайте до файлів сайту.

6. Розгорніть лише потрібну функцію саме у проєкт цього сайту:

   ```powershell
   supabase functions deploy admin-management --project-ref thzyezzxksoiwiaqybiv
   ```

   `thzyezzxksoiwiaqybiv` — Project Ref з адреси `https://thzyezzxksoiwiaqybiv.supabase.co`. Якщо CLI покаже `Target: thzyezzxksoiwiaqybiv` і попросить підтвердити розгортання, перевірте, що це потрібний проєкт, і введіть `y`.

7. У Supabase Dashboard відкрийте проєкт → **Edge Functions**. У списку має з'явитися `admin-management` зі статусом **Active**. Її адреса матиме вигляд `https://thzyezzxksoiwiaqybiv.supabase.co/functions/v1/admin-management`.

Не додавайте `--no-verify-jwt`: функція має перевіряти сесію того, хто її викликає. У `supabase/config.toml` для неї вже встановлено `verify_jwt = true`.

### Ключі Edge Function

У коді функції використовуються `SUPABASE_URL`, `SUPABASE_ANON_KEY` і `SUPABASE_SERVICE_ROLE_KEY`. Supabase автоматично надає ці системні змінні Edge Function. Не створюйте їх як власні secrets, не вставляйте ключі в `index.ts` і не зберігайте їх у файлах сайту. `SUPABASE_SERVICE_ROLE_KEY` має залишатися лише на сервері; Edge Functions Secrets потрібні для додаткових власних секретів, якщо їх додасть майбутня версія функції.

Якщо встановлення Scoop заблоковане політикою робочого комп'ютера, альтернативно можна в Dashboard відкрити **Edge Functions → Deploy a new function → Via Editor**, створити функцію з назвою `admin-management` і вставити в редактор вміст `supabase/functions/admin-management/index.ts`. Перед публікацією перевірте в налаштуваннях функції, що перевірка JWT увімкнена.

## Крок 3. Оновіть файли сайту

Опублікуйте оновлені `index.html`, `app.js` та `styles.css` із цієї папки разом із чинними файлами сайту. Після оновлення перезавантажте сторінку. У сервісному worker змінено версію кешу, тому новий код завантажиться після оновлення вкладки.

## Використання

### Надати або забрати права адміністратора

Увійдіть як головний адміністратор → **Адмін**. Біля користувачів з'явиться кнопка **Надати адміна**. Для користувача з правами адміністратора ця кнопка дозволить їх забрати. Головні адміністратори показуються окремо й не мають кнопок видалення/зняття ролі.

### Додати адресу з іншого домену

У верхній частині адмінпанелі головного адміністратора введіть повну адресу, наприклад `name@gmail.com`, і натисніть **Додати виняток**. Дозволяється лише вказана адреса. Після цього людина може увійти через стандартний одноразовий код. Для відкликання дозволу натисніть **Видалити виняток** біля адреси.

Виняток потрібен лише для майбутньої реєстрації. Він не змінює адресу вже зареєстрованого користувача.

### Видалити користувача

Натисніть **Видалити профіль** і підтвердьте дію. Буде видалено Auth-користувача Supabase, його профіль та дані, для яких налаштовано каскадне видалення. Дію не можна скасувати. Не видаляйте профіль, якщо його дані потрібно зберегти.

## Перевірка роботи

- Спробуйте почати реєстрацію з новою адресою `@novaposhta.ua` — вона має пройти.
- Адреса іншого домену без винятку має бути відхилена при створенні нового Auth-користувача.
- Додайте цю адресу у винятки від головного адміністратора — реєстрація має стати доступною.
- Увійдіть як веб-адміністратор: він може керувати доступом до «Вільного часу» та видаляти звичайних користувачів, але не бачить керування адміністраторами/винятками.
- Видалення головного адміністратора має бути заблоковано і кнопка для нього не показується.
