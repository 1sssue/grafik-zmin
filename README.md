# Графік змін

Особистий веб-застосунок для співробітника, який працює за змінним графіком: показує його зміни в календарі, веде облік закритих чатів, перепрацювань і вільного часу та рахує аванс і зарплату. Інтерфейс українською, адаптований під телефон, є світла й темна теми.

Це статичний сайт (один файл `index.html`) плюс [Supabase](https://supabase.com) для бази даних і входу. Окремий сервер не потрібен: сайт можна розмістити на GitHub Pages, Netlify, Vercel чи Cloudflare Pages.

## Можливості

### Графік змін і календар
- Завантаження файлів графіка `.xlsx` (також `.xlsm`, `.xls`): кнопка «Додати файл» або перетягування файлів на сторінку. Місяць визначається автоматично, можна додати кілька місяців одразу.
- Перелік завантажених файлів («Файли»): можна ховати й показувати файл місяця або видаляти його.
- Місячний календар зі змінами всіх вибраних людей; перемикання місяців, кнопка «Сьогодні».
- Список «Люди»: пошук за прізвищем, галочкою додається колега до календаря. Зірочка (★) позначає основного користувача, для якого рахуються зарплата, перепрацювання та чати.
- Кольори змін налаштовуються: кожен тип зміни (07:00, 10:00, вихідний тощо) має свій колір і легенду над календарем.
- У календарі позначені дні виплат: «Зарплата» (7-го) та «Аванс» (22-го). Якщо дата випадає на вихідний, виплата переноситься на попередню п'ятницю. Над календарем показано найближчі виплати та скільки днів лишилось.
- Блоки можна розгортати на весь екран кнопкою ⤢.

### Сьогодні
- Зміна, обід і перерва основного користувача на поточний день.
- Поля «Загальна кількість» і «Відкладені» чатів, розрахунок закритих чатів, норми та того, скільки лишилось до норми або на скільки норму перевиконано.
- Норма: 7,5 чата за годину; 9 чатів за годину, якщо ввімкнено доплату за кількісний. Перепрацювання додаються до норми.

### Закрито чатів
- Список чатів по днях місяця, сума за місяць, середнє на день і за годину, найкращий день, скільки лишилось до місячної норми.
- Графік чатів по днях із кольорами: зелений (норма виконана), жовтий (від половини норми), червоний (менше половини).

### Перепрацювання
- Додавання днів перепрацювання через міні-календар, для кожного дня кілька часових інтервалів і множник оплати (за замовчуванням ×1,5).
- Підсумок за місяць: кількість годин і сума.
- Перепрацювання враховуються в календарі, нормі чатів і зарплаті.

### Розрахунок зарплати
- Вводяться ставка за годину та розряд фахівця: Стажер (0%), Фахівець (10%), Фахівець 2 розряд (22%), Фахівець 3 розряд (35%) премії.
- **Аванс** = зміни 1–15 числа. **Зарплата** = зміни 16–кінець місяця + премія від усіх змін місяця + перепрацювання + доплата за кількісний. Окремо показується загальна сума.
- Доплата за кількісний (галочка): якщо середнє за місяць понад 9 чатів за годину, кожен чат понад `9 × години` дає 7 (значення `QB` у `index.html`).
- Суми показуються в цілих числах, без копійок. Валюта вибирається в налаштуваннях: гривня, долар, євро, злотий, фунт.

### Вільний час (за дозволом адміністратора)
- Облік вільного часу по днях місяця: кілька інтервалів «від–до» на день, сума за місяць і середнє за день.
- Блок видно лише тим, кому адміністратор надав доступ.

### Мобільна версія та PWA
- На екранах до 760 px показується окремий мобільний дизайн; на ПК інтерфейс не змінюється.
- Зверху назва місяця та кнопки «Файли» й «Налаштування» (тема, валюта, кольори змін, імпорт / експорт, адмін-панель, вихід).
- Знизу меню: «Календар», «Сьогодні», «Закрито чатів», «Перепрацювання», «Зарплата» і «Вільний час» (лише якщо адмін дав доступ).
- Календар на весь екран: зміни показані блоками «початок / кінець». Місяць перемикається свайпом угору (наступний) і вниз (попередній). Дні виплат позначені «ЗП» та «АВАНС».
- Кругла кнопка праворуч внизу відкриває список людей для відстеження.
- Застосунок можна встановити на телефон (PWA): у Chrome «Встановити застосунок» / «Додати на головний екран», в Safari «Поділитися» → «На екран Додому». Оболонка працює офлайн, дані завантажуються з бази після появи інтернету. PWA працює лише з `https://` (GitHub Pages підходить).

### Вхід, дані та адміністрування
- Вхід за одноразовим кодом із пошти, без паролів. Після входу сесія зберігається, і повторно вводити пошту не потрібно.
- Усі дані (чати, перепрацювання, вільний час, налаштування, файли графіків) зберігаються в базі й синхронізуються між пристроями автоматично, із затримкою близько 1,5 с.
- Кожен користувач бачить лише власні дані (правила RLS у `schema.sql`).
- «Імпорт / Експорт»: збереження даних у файл і відновлення з файлу (режими «Об'єднати» та «Замінити»). Графіки змін `.xlsx` в експорт не входять, їх додають окремо.
- «Адмін» (для адміністраторів): список користувачів, видача й відкликання доступу до блоку «Вільний час».
- До входу сайт показує приклад із вигаданими іменами.

## Налаштування

### 1. Supabase
1. Створіть проєкт на https://supabase.com (безкоштовного тарифу достатньо).
2. **SQL Editor**: відкрийте `supabase/schema.sql`, замініть три пошти `adminN@example.com` на пошти адміністраторів і натисніть Run.
3. **Authentication → Providers → Email**: увімкніть Email.
4. **Authentication → Email Templates**: у шаблонах **Magic Link** і **Confirm signup** замініть посилання на код: `Ваш код входу: {{ .Token }}`. Без цього листи прийдуть із посиланням, а не з кодом.
5. **Authentication → URL Configuration**: у *Site URL* вкажіть адресу сайту (див. п. 3).
6. Вбудована пошта Supabase має жорсткий ліміт листів на годину. Для постійного використання підключіть свій SMTP (Authentication → SMTP Settings, наприклад Resend чи Brevo).
7. **Project Settings → API**: скопіюйте *Project URL* і *anon public key* у `config.js`. Anon key публічний, захист даних забезпечують правила RLS.

### 2. GitHub
```bash
git init && git add . && git commit -m "Графік змін"
git branch -M main
git remote add origin https://github.com/<ваш-логін>/<назва-репозиторію>.git
git push -u origin main
```

### 3. Хостинг
Найпростіше GitHub Pages: репозиторій → Settings → Pages → Branch `main`, папка `/ (root)`. Адреса буде `https://<логін>.github.io/<репозиторій>/`. Підійдуть також Netlify, Vercel, Cloudflare Pages.

## Ролі
- **Адміністратори** (3 пошти з `admin_emails`): бачать кнопку «Адмін», видають і забирають доступ до «Вільного часу», самі мають цей блок.
- **Звичайний користувач**: свій графік, чати, перепрацювання, зарплата. Блок «Вільний час» з'являється, коли адмін надасть доступ.
- Адміністратори бачать список користувачів, але не їхні графіки та дані.

## Структура проєкту
- `index.html`: увесь застосунок (розмітка, стилі, скрипти, мобільний дизайн).
- `manifest.webmanifest`, `sw.js`, `icons/`: PWA (встановлення на телефон, офлайн-оболонка, іконки).
- `config.js`: адреса й публічний ключ Supabase.
- `supabase/schema.sql`: таблиці `profiles`, `user_state`, `admin_emails` і правила доступу.
- Зовнішні бібліотеки підключаються з CDN: `supabase-js` (вхід і база), `SheetJS` (читання `.xlsx`).

## Нотатки
- Якщо відкрити сайт на двох пристроях одночасно, діє принцип «останній запис перемагає».
- Для читання `.xlsx` і входу потрібен інтернет (бібліотеки з CDN).

## Shared schedule
1. For an existing database, run supabase/shared_schedule_files.sql in Supabase SQL Editor.
2. An administrator adds a local Excel file through Files → Add Excel. The parsed schedule is stored in Supabase and shown to all authenticated users.
3. Only administrators can add, hide, or delete schedules. Supabase RLS also enforces these permissions.
