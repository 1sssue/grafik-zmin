# Автоматичне оновлення графіка з Google Таблиці

## Як це працює

1. Адміністратор зберігає посилання на Google Таблицю у вікні **Файли** на сайті.
2. Google Apps Script, запущений від вашого Google-акаунта, перевіряє доступ до таблиці й час її останньої зміни.
3. Якщо файл змінився або натиснули **Оновити зараз**, скрипт читає таблицю, перетворює її на формат графіка сайту та записує дані в Supabase.
4. Усі користувачі сайту отримують спільні графіки під час входу. Відкритий сайт також оновлює їх приблизно раз на хвилину.

Автоматична перевірка виконується приблизно раз на хвилину. Google не гарантує запуск тригера в конкретну секунду, тому щойно внесені в таблицю зміни можуть з'явитися із затримкою до кількох хвилин.

## Що знадобиться

- Google-акаунт, якому дозволено відкривати таблицю.
- Доступ адміністратора до Supabase цього сайту.
- Посилання саме на Google Таблицю. Якщо джерело — файл Excel на Google Drive, спершу відкрийте його в Google Таблицях і збережіть як Google Таблицю.

Apps Script працює від імені акаунта, який створив тригер. Іншим користувачам таблиці Google-доступ надавати не потрібно: сайт передає їм опублікований графік через Supabase.

## Крок 1. Додайте таблицю налаштувань у Supabase

1. Увійдіть у [Supabase Dashboard](https://supabase.com/dashboard) і виберіть проєкт сайту.
2. У меню зліва відкрийте **SQL Editor**.
3. Натисніть **New query**.
4. Відкрийте файл `supabase/shared_schedule_files.sql` у папці сайту, скопіюйте весь його вміст та вставте у SQL Editor.
5. Натисніть **Run**. Успішне виконання створить таблицю `shared_schedule_source` для посилання й стану синхронізації. Скрипт безпечно можна виконати повторно.

Якщо вже запускаєте повний файл `supabase/schema.sql`, можна замість цього повторно виконати його. Окрему міграцію і повну схему одночасно запускати не потрібно.

## Крок 2. Створіть Apps Script

1. Відкрийте [script.google.com](https://script.google.com) під тим Google-акаунтом, який має доступ до графіка.
2. Натисніть **Новий проєкт**.
3. У редакторі відкрийте файл `Code.gs`, видаліть початковий приклад `myFunction` і вставте весь вміст локального файлу `apps-script/Code.gs`.
4. Натисніть **Зберегти** та назвіть проєкт, наприклад `Синхронізація графіка змін`.

### Додайте файл маніфесту

1. У Apps Script натисніть **Налаштування проєкту** (значок шестерні ліворуч).
2. Увімкніть **Показувати файл маніфесту «appsscript.json» у редакторі**.
3. Поверніться до редактора. У списку файлів з'явиться `appsscript.json`.
4. Відкрийте локальний `apps-script/appsscript.json`, скопіюйте весь вміст і замініть ним вміст `appsscript.json` у редакторі Google.
5. Збережіть проєкт.

Маніфест задає часовий пояс Києва та дозволи на доступ до Google Таблиць (потрібен `spreadsheets` для `SpreadsheetApp.openById`), читання Drive, HTTPS-запити до Supabase й створення тригера Apps Script.

## Крок 3. Додайте секрети Supabase в Apps Script

Секретний ключ потрібен серверному скрипту, щоб публікувати графіки в Supabase. Його не можна вставляти в `Code.gs`, `config.js`, інші файли сайту чи надсилати в чат.

1. У Supabase відкрийте **Project Settings → API** (у деяких версіях інтерфейсу — **Project Settings → API Keys**).
2. Скопіюйте **Project URL**. Для цього сайту він має виглядати як `https://thzyezzxksoiwiaqybiv.supabase.co`.
3. На цій самій сторінці знайдіть серверний ключ із правами `service_role` або позначений як **secret/service_role**. Скопіюйте його приватно. Не використовуйте `anon` / `publishable` key: у нього немає прав публікувати графіки.
4. У Apps Script відкрийте **Налаштування проєкту → Властивості скрипту → Додати властивість скрипту**.
5. Додайте першу властивість:
   - **Властивість:** `SUPABASE_URL`
   - **Значення:** URL проєкту Supabase, скопійований на кроці 2.
6. Додайте другу властивість:
   - **Властивість:** `SUPABASE_SERVICE_ROLE_KEY`
   - **Значення:** секретний серверний ключ Supabase.
7. Збережіть властивості.

Не додавайте ці значення до файлів проєкту і не публікуйте Apps Script із секретом у вихідному коді. У цій реалізації ключ зберігається окремо у властивостях скрипту.

## Крок 4. Запустіть і надайте дозволи

1. Поверніться до редактора коду Apps Script.
2. У списку функцій біля кнопки **Виконати** виберіть `setupSync`.
3. Натисніть **Виконати**.
4. Google попросить надати дозволи. Виберіть той самий робочий акаунт, який має доступ до Google Таблиці.
5. Перегляньте запитані права й підтвердьте читання таблиць/файлів та виконання зовнішніх запитів. Скрипт читає дані таблиці і надсилає розібраний графік до Supabase.
6. Якщо Google показує попередження про неперевірений скрипт, це очікувано для вашого особистого скрипту: відкрийте **Додатково** та продовжте лише якщо це проєкт, який ви щойно створили й перевірили.
7. Якщо запуск або синхронізація раніше завершилися помилкою про відсутній дозвіл, замініть маніфест на оновлений `apps-script/appsscript.json` з папки проєкту та збережіть його. У ньому мають бути `https://www.googleapis.com/auth/spreadsheets` і `https://www.googleapis.com/auth/script.scriptapp`.
8. Знову виберіть `setupSync` і натисніть **Виконати**. Google має повторно показати вікно дозволів. Підтвердьте новий доступ до таблиць і керування тригерами. Якщо вікно не з'явилося, оновіть редактор Apps Script і повторіть запуск.
9. Після успішного запуску Apps Script створить тригер `syncSchedule` з інтервалом приблизно в одну хвилину та виконає початкову перевірку. Джерело таблиці на цьому етапі ще може бути не додане — тоді початкова перевірка просто завершиться без синхронізації.

### Якщо Google не надає дозволи

Перевірте, що відкрили скрипт під робочим Google-акаунтом, якому доступна таблиця, і що адміністратор Google Workspace дозволяє Apps Script та зовнішні запити. Не потрібно створювати Google Cloud OAuth Client ID для цього способу.

## Крок 5. Додайте посилання на сайті

1. Відкрийте сайт і увійдіть під обліковим записом адміністратора.
2. Відкрийте розділ **Файли**.
3. У блоці **Автооновлення з Google Таблиць** вставте повне посилання, наприклад:
   `https://docs.google.com/spreadsheets/d/ВАШ_ID_ТАБЛИЦІ/edit?usp=sharing`
4. Натисніть **Додати посилання**. Сайт збереже адресу й ідентифікатор таблиці.
5. Скрипт перевірить це джерело під час найближчого запуску. Перша синхронізація може зайняти хвилину або трохи більше.
6. Після цього в блоці з'явиться час останньої синхронізації. Кнопка **Оновити зараз** поставить запит для найближчої перевірки.

Якщо потрібно підключити іншу таблицю, вставте її URL у поле та натисніть **Змінити посилання**. Якщо натиснути **Видалити посилання**, сайт попросить підтвердження, видалить посилання та прибере графіки, синхронізовані саме з цього джерела. Завантажені окремо Excel-файли це не зачіпає.

## Формат таблиці

Скрипт читає лише першу вкладку книги (у наданому файлі це `ЛИСТОПАД`). Дати змін шукаються в рядку серед перших 12 рядків; у рядку має бути щонайменше 20 дат. Імена працівників очікуються у стовпці C, години роботи — у стовпці E. Перший день починається у стовпці H; для кожного дня беруться 4 послідовні клітинки: початок, обід, перерва, тип роботи. Наступний день починається через 4 стовпці. Працівником вважається рядок з ім'ям у стовпці C та кодом у A/B або заповненими клітинками графіка. Рядки «Керівники груп» і «Група 1» тощо використовуються лише як заголовки груп. Часові клітинки читаються без перетворення часового поясу, щоб 13:00 не зсувалося на 15:02.

## Перевірка та усунення проблем

- **Помилка про таблицю `shared_schedule_source`:** крок 1 не виконано або SQL запущено в іншому Supabase-проєкті.
- **`Invalid API key` або помилка 401/403 від Supabase:** перевірте `SUPABASE_URL` та `SUPABASE_SERVICE_ROLE_KEY` у властивостях Apps Script. Переконайтеся, що вставили саме серверний `service_role` / secret key, без зайвих пробілів.
- **Помилка доступу до файла Google:** тригер створено під акаунтом, якому файл недоступний, або вставлене посилання не на Google Таблицю.
- **Працівники пропущені або зайві:** перевірте, що потрібний графік розташовано на першій вкладці, ім'я — у стовпці C, а дати й зміни — у рядках/колонках того самого аркуша. Оновіть код Apps Script з локального `apps-script/Code.gs`, збережіть і натисніть **Оновити зараз** у вікні файлів на сайті.
- **Помилка, що не знайдено таблицю змін:** перевірте рядок дат, стовпець C з іменами та відповідність структури аркуша файлу Excel, який читає сайт.
- **Де подивитися подробиці:** Apps Script → **Виконання**. Відкрийте невдалий запуск `syncSchedule`, щоб побачити текст помилки.
- **Зупинити автоматичну перевірку:** Apps Script → **Тригери** (значок годинника) → видаліть тригер `syncSchedule`. Функцію `setupSync` повторно запускайте лише якщо потрібно створити тригер знову.

Скрипт читає Google Таблицю з правами власника тригера. Користувачам сайту таблиця Google не відкривається: вони бачать лише графік, опублікований у Supabase.
